Packet Switching v.s. Circuit Switching

Packet

  • 網路傳送的是封包。
  • 傳送資料會被切成封包。

計算封包傳輸 Delay

dtrans = Transmission Delay = L（bit）R（Transmit Rate）

↳ L ← 傳輸資料大小（Size）；R ← 速率（Bandwidth）。

Packet Switching

  • 同一條線路多人共享頻寬。
  • 適合同一時段較少人傳送資料。
  • 同一時間可以多人在線。

Feature 1

Formula

D = (N + P − 1) LR

↳ N：Link 數量（Router 數量＋1）
P：Packet amount。

Ex：(2 + 3 − 1) LR = 4 LR

＊ 等長 packets、各 link 同速率、store-and-forward；忽略 propagation、processing 與額外 queueing delay。

Feature 2

Circuit Switching　專線

  • 不與他人共享已分配的頻寬。
  • 可能會閒置。
  • No queue delay，但可能忙線。

↳ Ex：傳統電話線。

DNS Record　補齊

Resource Record（RR）

(name, value, type, TTL)

↳ Name：這筆 record 的名稱。Value：依 type 決定代表什麼。

↳ TTL：可以被 cache 的時間（秒）；到期後不再直接當作有效快取使用。

A　Hostname → IPv4 Address

  • Name：hostname。
  • Value：IPv4 address。
(www.example.com, 192.0.2.10, A, 3600)

↳ 問 www.example.com 的 IPv4 → 192.0.2.10。

NS　Domain → Authoritative DNS

  • Name：domain / zone name。
  • Value：這個 domain 的 authoritative name server 的 hostname。
(example.com, ns1.example.com, NS, 86400)

↳ 要問 example.com 的資料 → 找 ns1.example.com。

＊ NS 的 value 是 DNS server 的名字，不是 IP；要連到它，還要取得它的 IP。必要時 delegation 會附 glue address。

CNAME　Alias → Canonical Name

  • Name：alias name（別名）。
  • Value：canonical hostname（真正指向的名稱）。
(video.example.com, edge.cdn.example.net, CNAME, 300)

↳ 查 video.example.com → 再查 edge.cdn.example.net → 取得 IP。

＊ CNAME 不是 HTTP redirect；DNS 只是在名稱解析時指向另一個名稱。

MX　Domain → Mail Server

  • Name：收信的 domain。
  • Value：mail server hostname，另含 preference / priority。
(example.com, 10 mail.example.com, MX, 3600)

↳ 寄到 user@example.com → 查 example.com 的 MX → 找 mail.example.com。

↳ 數字越小，優先程度越高；再查 mail server 的 A / AAAA 取得 IP。

Application Layer　CDN

CDN

↳ Issue to resolve：資料在同一個 Server，每次重新取得太耗時，吃效能。

↳ Solution：把 content copies 分散到多個地點。

  • 距離使用者近。
  • 有 Video Cache，速度快。

＊ 前提：CDN server 要加到 cache & cache not expired。

How to Deploy

Enter deep

  • CDN servers 深入很多 access networks。
  • 離使用者近；分散的站點多。

Bring home

  • 較少、較大的 clusters。
  • 放在接近 access networks 的 POPs。

Content Access

  • Client 取得影片 URL → 問 Local DNS。
  • 網站的 Authoritative DNS 回傳 CDN 的 CNAME。
  • Local DNS 繼續查 CDN 的 Authoritative DNS → 取得 CDN server IP。
  • Client 用 HTTP 向 CDN server 取得 video。

＊ DNS 解析的是 hostname；影片 path 由 HTTP request 傳送。

Netflix　／　DASH

  • Client 管理 Netflix account → browses video。
  • 取得該影片的 manifest file → 選擇 DASH server → streaming。
  • Video 分成多個 chunks；每個 chunk 有不同 bit rate 的版本。
  • Manifest file → 各版本 chunks 的 URL。
  • Client 依可用頻寬、buffer，選下一個 chunk 的版本。

Streaming video = encoding + DASH + playout buffering。

OTT　Over the Top

附近的 copy 不一定只是地理距離近；network path congested 時，可以選不同 copy。

Socket Programming

Goal

  • Build client / server applications，透過 sockets 通訊。

UDP Socket

  • No connection；no handshaking before sending。
  • 每次 sendto → 指定 destination IP + port。
  • recvfrom → 取得 data + sender IP / port。

↳ 資料可能 lost 或 out-of-order。

Server：socket → bind → recvfrom → 處理 → sendto。

Client：socket → sendto → recvfrom → close。

TCP Socket

  • Server 先 running，建立 welcoming socket。
  • Client connect → 建立 TCP connection。
  • Server accept → 與該 Client 溝通的 connection socket。

↳ Welcoming socket 繼續等待其他 Client。

Server：socket → bind → listen → accept → recv / send → close。

Client：socket → connect → send / recv → close。

Application Example

↳ TCP：reliable、in-order byte stream；UDP：unreliable datagrams。

UDP　／　Reliable Data Transfer

UDP　User Datagram Protocol

Checksum

  • 檢查封包的資料是否正確（有無 bit error）。
  • 封包丟失不會重送（UDP 本身）。

Reliable Data Transfer

Stop and Wait

  • rdt 2.x、rdt 3.0 基本版本都是用 stop-and-wait。
  • Sender 送出封包 → 等待確認送達 → 下一個 packet。

rdt 1.0

假設傳輸是 Reliable → 不現實。

rdt 2.0

假設 bit error 會發生。

New feature：Checksum → detect bit error。

rdt 2.1

  • ＋ Sequence number，但是 1 bit（0、1）。
  • 透過 0、1、0、1 來辨識封包順序／重複。
  • ACK / NAK 的封包如果損毀就 resend。

↳ Seq number 讓 Receiver 能識別 duplicate，不重複交付上層。

rdt 2.2

移除 NAK，改用 ACK + seq num 來判斷有沒有抵達。

↳ Sender 等待下一個封包的 ACK 時，連續收到 ACK1、ACK1 → 當前封包重送。

CH3↖ 目錄

Pipelining　／　Go-Back-N　／　Selective Repeat

rdt 3.0

  • 假設 packet 會 loss（data 與 ACK 都可能丟失）。
  • ＋ 有 timeout 的機制。

↳ When packet is sent → start a timer。

Pipelining　Increased Utilization

  • 解決 stop-and-wait 的低使用率。
  • Pipeline：一次傳送多個封包，同時接收 ACK。

Go-Back-N

Packet ID：依序往上（實際編號以有限序號空間循環）。

↳ pkt2 timeout → 重送 pkt2 與 window 內之後尚未確認的 packets。

↳ Receiver 丟棄 out-of-order packets，重複回覆最後連續收到的 ACK。

Selective Repeat

核心：僅重送 timeout 的 packet。

↳ 收到 out-of-order packet → 先暫存並回 ACK。

↳ 最前面的缺口補齊 → window 才能繼續往前。

TCP in Detail

＊ TCP header 最少 20 bytes = 5 × 32 bits = 5 個 words；options 可讓 header 變長。

RTT of TCP

  • TCP 的 RTT 值是 dynamic 的調整。
  • 需要估計 RTT 的原因：timeout 的估計。

Formula：

新 RTT 統計 ← 舊的統計＋本次 RTT 結果。

EstimatedRTTnew = (1 − α) EstimatedRTTold + α SampleRTT

α = 0.125。

DevRTTnew = (1 − β) DevRTTold + β |SampleRTT − EstimatedRTT|

β = 0.25。

↳ SampleRTT 與 EstimatedRTT 差異大 → DevRTT 較大。

TimeoutInterval = EstimatedRTT + 4 DevRTT

↳ RTT 變異程度大 → safety margin 較大。

TCP Sequence Num 及 ACK

ACK number 回傳期待收到的 byte 序號。

Feature：TCP 可以在同一個 connection 實現雙向同時傳送資料。

ACK、Sequence Number 如何判斷封包丟失

↳ Lost ACK → Sender timeout 後重送；Receiver 回覆 ACK。

↳ Premature timeout → 先收到 ACK100、再收到 ACK120 → 不再重送 Seq100。

↳ 有收到 ACK120 → Sender 知道 byte 119 以前都收到，包含先前 ACK100 確認的資料。

  • 限制 data 進入 Internet。

Difference

觀察方式

壅塞原因

cwnd 如何調整
